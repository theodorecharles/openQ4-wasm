# openQ4 0.9.0 Release Notes

## Highlights

- Multiplayer item readability is now configurable without replacing the original models: pickups can use icon-matched flat diffuse colours and an optional soft upward lightness sweep while retaining authored bubbles, normal maps, highlights, glow, and other effects. First-person weapons stay untouched, and flat colouring for opponent-held weapons is a separate option.
- Multiplayer bots now feel like distinct characters instead of interchangeable opponents: all sixteen have profile-driven playstyles and difficulty bands, including individual trigger initiative, target loyalty, wounded-target and revenge priorities, suppressive fire, strafe rhythm, weapon-switch timing, and aim height. Lower skill levels enter fights and pull the trigger more readily while keeping their intentionally poor aim. The roster also has 2,350 character-appropriate lines in dedicated voice files; bots recognise conversational cues from players and other bots, prefer the character addressed by name, and answer in character without setting off reply chains.
- Experimental Vulkan rendering has taken a major step forward. The opt-in renderer now covers stock world geometry, interaction lighting, stencil and mapped shadows, fog and blend lights, post-processing, SMAA, material-program effects, and common gameplay subviews while retaining a safe OpenGL fallback if it cannot initialize.
- Saving a game while using Vulkan no longer flashes the 320x240 save-preview render in the bottom-left corner of the display. Save previews are captured without presenting their temporary cropped frame.
- Linux desktop support is more robust across Wayland, X11 fallback, high-DPI displays, input-focus changes, PipeWire-optional audio startup, AppImages, and ARM64 package validation.
- Game and engine portability checks now cover more Linux x64/ARM64 and macOS failure cases, including stricter module ABI, save/load, startup, package, and sanitizer validation.
- Windows, Linux, and experimental macOS packaging now carry stronger runtime and symbol-validation checks, making release artifacts easier to install and diagnose. macOS app packages also preserve their startup splash resource correctly.

## Upgrade Notes

- Stock multiplayer pickup rendering remains the default. To change it, open `Settings -> Game Options`, choose a `Pickup Style`, and optionally enable flat colouring for weapons held by opponents; neither setting affects server rules or other players.
- OpenGL remains the default renderer. To try Vulkan, set `r_renderApi vulkan` and restart the engine; it is still experimental, so report visual problems with `openq4.log` and your GPU/driver details.
- Replace an existing openQ4 package with the matching new archive or installer. Keep your retail Quake 4 assets separate from openQ4's `baseoq4/` runtime files.
- Linux ARM64 downloads remain preview packages unless the release asset name explicitly says otherwise. Experimental macOS downloads remain Apple Silicon/arm64-only and may be unsigned when release signing credentials are unavailable.

## Change Log

- Fixed multiplayer bots getting stuck jumping below elevated pickups, including the two-crate route to q4dm1's yellow armour. Bots now commit to obstacle jumps through landing, keep other steering from disrupting the move, and avoid goals that are only connected by an unusable one-way route.
- Added whole-word, name-aware bot replies for greetings, requests for help, thanks, praise, apologies, challenges, farewells and post-match sportsmanship. Messages now wait briefly according to their visible length and show Quake 4's stock overhead typing icon while the bot composes them. Replies respect team chat and flood limits, and generated replies cannot trigger another reply.
- Added four client-local multiplayer pickup styles—original models, legacy simple icons, flat colour, and flat colour with an upward sweep—plus an independent flat-colour option for opponent-held weapons across the OpenGL and Vulkan interaction paths.
- Added the native Vulkan renderer's expanded lighting, shadow, post-process, material-program, capture, and render-target paths, with OpenGL retained as the default compatibility renderer.
- Prevented Vulkan save-preview readback from presenting its temporary cropped image before the normal gameplay frame is ready.
- Improved Linux Wayland/X11 lifecycle handling, text input, focus recovery, display changes, audio startup, dedicated-server isolation, and x64/ARM64 package validation.
- Expanded cross-platform safety checks around game modules, save games, rendering resources, package contents, symbols, release provenance, and diagnostics.
- Improved experimental macOS build, package, support-collection, and validation workflows while keeping its published support scope explicit.

## macOS Support Scope

- This remains experimental macOS support for Apple Silicon/arm64 only. Intel Mac,
  universal2, and Rosetta packages are not supported or published.
- The `-metal` package is a Metal bridge around the OpenGL renderer, not a native Metal renderer.
- `platform_backend=native` remains comparison-only diagnostic infrastructure, not a release backend.
- [GitHub issue #73](https://github.com/themuffinator/openQ4/issues/73) remains
  open until the new default is verified in SP and MP on real Apple hardware.
  Accepted signoff is still required on the documented macOS 11 floor and the
  latest public macOS in `docs/dev/macos-signoff-evidence.md` before support can
  be promoted beyond experimental.
- Unsigned archive builds are ad-hoc signed but are not Developer ID notarized;
  macOS may require explicit approval. See
  [Experimental macOS Support Data](../../user/macos-support-data.md) when
  reporting a failure.
